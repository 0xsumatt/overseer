How this works

Every five minutes the scheduler downloads each venue's public order book for {{ depth_config.assets | map(attribute='id') | join(', ') }}, in the same capture as the cheapest-venue history, and stores the resting size in 1 bps buckets out to ±{{ depth_config.window_bps }} bps from that book's mid, along with how far the book itself reached.

Blue cells are bids below the mid and purple cells asks above it; brighter means more size resting in that 1 bps band, on a square-root scale that reaches full colour at the 95th percentile of the cells in this window. The faint band is the part of the book each snapshot showed. Outside it the venue sent nothing, which is not the same as nothing resting: REST snapshots of Binance and Bybit BTC reach only about ±16 to 28 bps, and Hyperliquid's 20 levels about ±2.4 bps.

Around mid plots distance from each snapshot's mid in bps, so even a narrow book fills the chart and you can see how depth near the price changes. Price plots price levels instead, so orders resting at a fixed price line up across time; zoom in on the chart for a narrow book.

Longer windows show one stored snapshot per 30 minutes (7d) or per 2 hours (30d), never an average: buckets move with the mid, so averaging would smear price levels. A gap means no snapshot was stored. Prices are in the venue's own quote currency; USD amounts use the reference FX at capture.

Hover or touch the chart for the size in one bucket at that time; otherwise the line beneath summarises the latest snapshot.
